# 强势股二次启动研究：连续交接与运行约定

更新时间：2026-09-03（北京时间）

## 1. 工作模式

- 正常对话时，优先完成用户当前明确安排的任务。
- 无需逐步骤等待确认；在既定策略和资金边界内连续自主推进。
- 每个阶段保留独立结果、质量校验和审计文件，便于单独验收。
- 只有正式策略规则、资金规则、不可逆变更或新增权限才暂停确认。
- 研究结论不是收益承诺，也不是自动交易指令。

## 2. 正式筛选链路

1. 动态主池（当前约559只，加入每日新名单并按代码去重）抓取/增量维护25个交易日行情。
2. Python确定性粗筛到150–200只，同时输出全量主池维护审计。
3. Python抓取120日与250日结构/生命周期数据，压缩到30–50只。
4. OpenAI Responses API研究30–50只，输出0–10只次日观察池。
5. 次日14:40–14:45重新抓取实时数据，OpenAI Responses API最终确认0–5只；允许0只，不凑数。

数据抓取、缓存、指标计算、排序、文件生成由Python/GitHub Actions完成。OpenAI API只承担需要综合判断的后两层，以降低模型流量和运行成本。

## 3. 每日名单上传

- 兼容标准XLSX、标准XLS，以及行情软件导出的GBK/GB18030/UTF-16制表符“伪XLS”。
- 文件可以只有“名称”列。系统优先读取仓库内的 `v5_data/reference/a_share_code_name_master.csv` 补全代码，再使用在线接口补充。
- 名称存在歧义或确实无法匹配时必须明确报出未匹配项，不允许静默猜代码。
- 今日实际上传文件解析为72只有效股票；45只主池已存在、27只新增，合并后主池559只。

## 4. 动态主池和行情缓存

- 新增股票抓取所需完整历史窗口；已缓存股票只补新增交易日，再滚动保留所需窗口。
- 股票从主池淘汰后进入可审计归档，不物理遗忘；以后再次出现在每日强势名单时可自动重新激活。
- 当前淘汰规则仍采用“较久未再次提交且趋势同步转弱”的双重条件。25日短期走弱可以降级/冷却，但在规则未经回测验收前不直接硬删除，避免误杀平台整理标的。
- 2026-09-03运行中主池559只，淘汰0只；这是规则结果，不代表系统漏做维护。

## 5. OpenAI API审计

- 盘后30–50到0–10和次日0–5必须实际调用 `OpenAI().responses.create(...)`。
- 缺少 `OPENAI_API_KEY` 或API失败时，流程必须失败并推送故障，不得伪造“AI已完成”结果。
- 每次成功调用在Actions日志记录：北京时间、response_id、实际模型、input_tokens、output_tokens、total_tokens；不记录密钥。
- 原始模型JSON、解析后的决策及失败文件均保存在对应运行目录。
- 2026-09-03的40→4已有完整原始模型JSON，但当时版本尚未记录response_id/token；因此能证明代码走API并获得了结构化响应，不能仅凭旧日志完成逐笔账单核对。新审计从后续调用开始生效。

## 6. 无人值守与权限边界

- 正式无人值守执行器是GitHub Actions，不依赖ChatGPT聊天窗口保持在线，也不依赖Plus用量是否已重置。
- 必要Secrets：`OPENAI_API_KEY`、`PUSHPLUS_TOKEN`；仓库内任务使用GitHub提供的Actions token完成已声明的提交。
- 日常抓取、筛选、API调用、结果提交和推送不应再请求临时授权。
- ChatGPT/Codex的安全审批不能通过“永久全部授权”绕过；删除、外部发布等高风险动作仍可能要求人工确认。
- ChatGPT Plus与OpenAI API是两套独立计费/限额。聊天达到上限不应阻断Actions；API自身额度、项目、组织和密钥仍需单独有效。
- ChatGPT自动化只做巡检和恢复辅助，不能作为绕过Plus用量上限的机制。

## 7. 通知验收

- 2026-09-03盘后运行日志显示PushPlus请求成功；因旧版本未记录返回code/msg，仍需用户确认微信端是否实际收到。

## 9. 市场与板块数据库升级要求

- 30–50只到0–10只，以及0–10只到次日0–5只，两次OpenAI判断都必须带入通过质量校验的市场与板块上下文。
- 市场日表滚动保存至少25个交易日：主要指数、总成交额及环比、上涨/下跌/平盘家数、涨停/跌停、炸板/触板、封板率、最高连板、昨日涨停溢价、市场宽度与风险状态。
- 板块日表滚动保存至少25个交易日：行业/概念涨跌、成交与资金净流入、涨停数量、连续强势天数、板块扩散度/集中度，以及每只候选股票对应板块。
- 结构化行情和板块数值以可交叉验证的数据源为正式口径；淘股吧公开复盘文章只作为热点命名、情绪叙事和事件解释的补充证据，必须保存来源URL、发布时间、抓取时间及解析质量，不能凭单篇帖子直接改变入选资格。
- 任一关键表缺失或跨源差异超过待验证标准时，板块层降级为“实验性未启用”；OpenAI提示词必须明确禁止臆测板块结论。
- 每日北京时间00:00由自动任务汇总当天可访问的对话决策、偏好、GitHub提交、运行结果、失败和待办，写入 `docs/daily_log/YYYY-MM-DD.md`。聊天原文不是可靠的长期数据库，因此正式规则仍须同步写入本交接文档和版本化配置。
