# V5端到端流程与稳定性审计（2026-09-06）

## 结论

主流程没有发现会静默生成错误推荐的现存阻断性Bug。日期锁、持仓排除、缺失数据门禁和失败不冒充“0只”均存在。当前可靠性不是“全部生产验收完成”：新盘后七阶段和新14:40/14:45双阶段仍需下一次真实上传、下一交易日分别验收；交易台账需用户配置密钥；概念映射和近10日资金流仍有上游降级。

评级口径：A=真实生产或同等云端实测通过；B=代码、确定性测试和云端结构通过，待真实业务窗口；C=可降级使用但外部源不稳定；D=阻断。

## 本次修复的可靠性问题

1. 盘后完成推送原先没有向工作流返回PushPlus成败；现保存`pushplus_delivery_ok`，失败使任务失败并告警。
2. 盘后微信失败后重跑原先可能再次执行OpenAI；现识别`completed_push_failed`，只重试发送。
3. 盘后任一中间阶段失败原先没有统一微信故障通知；现增加最终失败告警，不把失败解释为0只。
4. 淘股吧20:30任务若排队至21:40以后，原三个发送窗口可能全部错过；现汇总完成立即发送，21:00/21:20/21:40作为兜底并按摘要指纹去重。
5. 辅助尾盘数据测试把周末没有当日5分钟K误判成接口故障；现非交易日明确跳过严格K线门槛，交易日仍严格要求逐股完整。
6. 自动工作流增加永久超时预算测试；所有日常自动任务单作业不超过10分钟。旧全市场多年历史抓取改为手动研究专用，不再随代码提交自动运行。
